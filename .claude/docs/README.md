# PocketInBox — дока

Единый источник знаний о проекте. Начинать чтение отсюда.

## Структура

| Раздел | Что лежит | Когда обновлять |
|---|---|---|
| [product/](product/) | Что за приложение, сценарии, экраны, доменные сущности | Меняется продуктовая идея или появляется фича |
| [architecture/](architecture/) | Текущее состояние: стек, модули, слои, паттерны | Меняется устройство кода |
| [decisions/](decisions/) | ADR — почему принято то или иное решение | Принимается новое значимое решение |
| [conventions/](conventions/) | Правила написания кода, нейминг, git | Договорились о новом правиле |
| [roadmap.md](roadmap.md) | Текущий этап, ближайшие шаги, открытые вопросы | Каждый завершённый или начатый этап |

## Правила ведения

- `architecture/` описывает **что есть сейчас**, `decisions/` — **почему так**. Не дублировать: в architecture ссылаться на ADR.
- ADR не переписываются задним числом. Если решение меняется — новый ADR со статусом `Supersedes ADR-XXX`, у старого статус `Superseded by ADR-YYY`.
- Каждый раздел имеет свой `README.md` с оглавлением. Новый файл — сразу строка в оглавлении раздела.
- Один файл — одна тема. Если файл разрастается за пределы одной темы, делить.
